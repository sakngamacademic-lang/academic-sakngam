## Migration (ต้องขออนุมัติก่อนรันบน Staging — ยังไม่ได้รัน)
`supabase/migrations/20261203000100_curriculum_categories_criteria.sql` — เพิ่ม 3 ตาราง + 4 RPC (ไม่แก้ข้อมูลเดิม)
- `curriculum_category_links` หมวด↔รายวิชา/แผน/กิจกรรม (หลายหมวดได้ · เหตุผลบังคับ · ตรวจว่าเป้าหมายมีจริงในฉบับ)

- เขียนได้เฉพาะ `academic_head` ผ่าน RPC · อ่านได้ตามสิทธิ์ผู้อ่านหลักสูตร · Audit ทุกแถว

## กฎจัดหมวดสมรรถนะอาชีพ (ปรับปรุง 18 พ.ย. 2569)
รอบแรกจัดหมวดจากแผนทวิศึกษาเท่านั้น จึงไม่พบ ม.ต้น — แก้แล้วให้ตรวจ **คำอธิบายรายวิชา + ผลการเรียนรู้** ด้วย (ไม่ใช่การรับรองสมรรถนะ)
| ระดับหลักฐาน | เงื่อนไข |
|---|---|
| หลักฐานเชิงโครงสร้าง | เปิดสอนเฉพาะในแผนสายอาชีพ (ทวิศึกษา) |
| พบองค์ประกอบสมรรถนะในเนื้อหา | ทักษะปฏิบัติ **และ** มิติเศรษฐกิจ (การตลาด/จัดจำหน่าย หรือ บัญชี/ต้นทุน/กำไร) |
| พบองค์ประกอบบางส่วน | (กลุ่มสาระการงานอาชีพ) ทักษะปฏิบัติ/การมุ่งอาชีพ แต่ไม่พบมิติเศรษฐกิจ |
| พบคำสำคัญเท่านั้น | คำ “อาชีพ/ช่าง/บัญชี/ธุรกิจ” ในชื่อวิชาเท่านั้น |
| ข้อมูลไม่เพียงพอ | วิชาเพิ่มเติมกลุ่มการงานอาชีพที่ไม่มีคำอธิบายและผลการเรียนรู้ในระบบ |

ผลกับข้อมูลจริง 2569 (อ่านอย่างเดียว):
- **ม.ต้น:** เนื้อหา 4 (ง21261 ขนมไทย, ง21262 พืชผักสวนครัว, ง22264 ไม้ดอกไม้ประดับ, ง23266 ผลิตกล้าไม้) · บางส่วน 1 (ง22263 ถนอมอาหาร — มีทักษะปฏิบัติ/การมุ่งอาชีพ แต่ระบบไม่มีข้อความการจำหน่าย/บัญชี) · ข้อมูลไม่เพียงพอ 1 (ง23265 ผ้าและการซ่อมแซม — ระบบมีเฉพาะหน้าโครงสร้าง pdf:16 ไม่มีคำอธิบาย/ผลการเรียนรู้)
- **ม.ปลาย:** โครงสร้าง 89 · เนื้อหา 4 · บางส่วน 12 · คำสำคัญ 2 · ข้อมูลไม่เพียงพอ 1
- กันผลบวกลวง: ศ23202 นาฏศิลป์, ท23201 ห้องสมุด (“จำหน่ายออกจากห้องสมุด”), ว21201, ว20286 ไม่ถูกจัดเป็นอาชีพแล้ว

## ผลตรวจ Migration 20261203000100 ก่อนติดตั้ง
| ด้าน | ผล |
|---|---|
| ผลกระทบข้อมูลเดิม | สร้างตารางใหม่ 3 ตารางเท่านั้น — ไม่มี `alter/update/delete` ตารางเดิม · FK ไป `curriculum_versions`/`source_documents` เป็น `on delete restrict` (เมื่อมีการจัดหมวดแล้วจะลบฉบับ/เอกสารนั้นไม่ได้ — ตั้งใจเพื่อรักษาหลักฐาน) |

| สิทธิ์เขียน | ผ่าน RPC security definer (`search_path=''`) เท่านั้น · ตรวจ `require_human` + `academic_head` · ตรวจฉบับ/เป้าหมาย/เอกสารอยู่โรงเรียนเดียวกัน · helper ส่วนตัวไม่ให้สิทธิ์ authenticated |

## นำเข้าเกณฑ์ระดับ 5 จากต้นฉบับ
- ลงทะเบียน/อัปโหลดแบบประเมินที่หน้า “นำเข้าเอกสารหลักสูตร” (ระบบรับ PDF — ภาพให้สแกนรวมเป็น PDF)
- หน้าภาพรวมหลักสูตร → หมวด → “นำเข้าเกณฑ์จากต้นฉบับ” → วางข้อความตามต้นฉบับ พร้อม `หน้า N`, `ระดับ 5`, เลขข้อ `1.` `1.1` `(1)` → ตรวจตัวอย่าง (เปิด PDF หน้าที่อ้างได้) → บันทึกเป็นร่าง
- ระบบไม่แต่งข้อความ ไม่สร้างค่าขั้นต่ำ ไม่ยืนยันเกณฑ์ — ผู้ดูแลตรวจกับ PDF แล้วกด “ยืนยันเกณฑ์” ทีละข้อ (ตัวแยกข้อความ: `scripts/criteria-import.test.ts` 4/4)

## วิเคราะห์หลักสูตรจากเอกสาร (ปุ่มเดียว · 18 พ.ย. 2569)
- ใช้รายวิชา 2569 (ชื่อ คำอธิบาย ผลการเรียนรู้ ระดับชั้น) + ตารางสาระท้องถิ่น (CSV) + ฐานตัวชี้วัดที่ระบบมี — `categories/local-match.ts` (deno `scripts/local-match.test.ts` 5/5)
- จับคู่: อักษรกลุ่มสาระ (ต → อ/จ/…) + ชั้นตามรหัส + **สาระแกนกลาง** ↔ เนื้อหารายวิชา (IDF) · สาระท้องถิ่นเป็นหลักฐานเสริม ไม่ใช้คะแนน · คำ “ท้องถิ่น/กำแพงเพชร” อย่างเดียวไม่จับคู่
- รหัสตัวชี้วัด: เก็บตามต้นฉบับ ไม่แก้/ไม่เดา · ตรวจได้เฉพาะกลุ่มสาระที่มีฐาน (ตอนนี้ ค/ว/ส5 จาก SRC-02 ที่ยังไม่รับรอง)
- ผลกับตารางจริง (367 แถว, ข้อมูลรายวิชาจริง อ่านอย่างเดียว): มั่นใจสูง 165 รายการ → 66 รายวิชา · ปานกลาง/ใกล้เคียงหลายวิชา 45 · หารายวิชาไม่ได้ 79 · ไม่มีรายวิชาชั้นนั้น 8
  รหัส: พบในฐาน 40 · ไม่พบในฉบับปรับปรุง (อาจเป็นรหัสเดิม) 30 · ตรวจไม่ได้ (ไม่มีฐาน ท/ศ/พ/ง/ต/ส1–4) 283 · รูปแบบไม่ชัดเจน 14
- ยืนยันแบบกลุ่ม: ผู้ดูแลเลือก/ตัดรายวิชาแล้วกดครั้งเดียว → `curriculum_category_set` (หมวดท้องถิ่น) พร้อมเหตุผล “ตาราง X แถว Y (รหัส)” — ไม่อัตโนมัติ ไม่แก้รายวิชา
- Migration รออนุมัติ `20261205000100_local_content_register.sql` (pgTAP 035 7/7): บันทึกตาราง CSV ตามต้นฉบับ (ชุดใหม่ไม่ลบชุดเดิม) — ก่อนติดตั้งวิเคราะห์ได้จากไฟล์ที่เลือกในเบราว์เซอร์ (ไม่บันทึก)
- เกณฑ์ระดับ 5: นำเข้าจาก PDF ที่ลงทะเบียน → ใช้ระบบอ่านเอกสารเดิม (`document_analysis_page_texts`) เติมข้อความพร้อม “หน้า N” → แยกข้อ → บันทึกเป็นร่าง · การกรอกเองย้ายเป็น “กรณีพิเศษ”
