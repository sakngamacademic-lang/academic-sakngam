- ยังไม่บันทึกฐานข้อมูล

- **ยังไม่พร้อมใช้จริงทั้งโรงเรียน** จนกว่าจะรัน Migration และต่อที่เก็บข้อมูลเข้ากับตาราง `cv2_*`

## 1. สิ่งที่เปลี่ยนจากระบบเดิม
| ระบบเดิม (Legacy) | V2 |
|---|---|
| เมนูหลักสูตร 6 กลุ่ม (รวมลิงก์ย่อย ~20 หน้า: Mapping, Coverage, CF, เกณฑ์, ตรวจข้อมูล ฯลฯ) | Sidebar “หลักสูตรสถานศึกษา” เหลือ **5 เมนู**: ภาพรวม · นำเข้า · โครงสร้างและรายวิชา · เปรียบเทียบ · รายงาน |
| ข้อมูลจากทะเบียนเดิม (subjects/subject_offerings) ที่ PDF/Excel ไม่ตรงกัน | ข้อมูลใหม่จากการนำเข้าไฟล์ แยก namespace (`/office/curriculum-v2`, ที่เก็บ V2) **ไม่ดึงข้อมูลเดิมมาแสดง** (ทดสอบแล้ว: 0 คำขอไปตารางเดิม) |
| นำเข้าผ่าน batch/CF หลายขั้น | อ่านไฟล์ → ตัวอย่าง + ประเด็น + อ้างอิงทุกแถว → ยืนยัน |
| ไม่มีหน้าเปรียบเทียบปี | เปรียบเทียบ 2568 ↔ 2569 จับคู่ด้วย รหัส/ชื่อ/กลุ่มสาระ/ชั้น/ตำแหน่งแผน กรณีไม่แน่ใจ = “รอตรวจทาน” |

**ระบบเดิมยังอยู่ครบ:**
- ทุก route และทุกสิทธิ์เดิมยังใช้ได้ ย้ายไปอยู่ในกล่องพับ “เครื่องมือฝ่ายวิชาการ → หลักสูตรเดิม (Legacy · ขั้นสูง)”
- ทุกหน้าเดิมมีแถบแจ้ง Legacy และลิงก์ไป V2
- หน้า `/teacher/curriculum` ของครูยังเป็นระบบเดิม

**การทำ Legacy ให้อ่านอย่างเดียวจริง:**
- ต้องเปลี่ยน RLS ของตารางเดิม ซึ่งถือเป็นการเปลี่ยนสิทธิ์ จึงไม่ได้ทำ
- ข้อเสนอ: ทำเป็น migration แยกที่ถอนสิทธิ์ insert/update ของบทบาทหลักสูตรบนตารางเดิม และต้องขออนุมัติ

## 2. โครงสร้างโค้ด (`src/features/curriculum-v2/`)
| ไฟล์ | หน้าที่ |
|---|---|
| `model.ts` | แบบข้อมูลกลาง, อ้างอิงแหล่ง (`Ref`: ไฟล์+ชีต/เซลล์ · หน้า PDF · ตาราง/แถว DOCX), กลุ่มสาระตามอักษรนำหน้ารหัส, ชั้นตามรหัส |
| `parsers.ts` | XLSX (ใช้ `structure-workbook.ts` เดิม), DOCX (อ่าน XML แบบนับความลึก รองรับตารางซ้อนและหัวตารางนอกตาราง), PDF (จัดบรรทัดจากพิกัด pdf.js แยกคอลัมน์ภาค 1/2), คำอธิบายรายวิชาแยกจากตารางโครงสร้าง |
| `loader.ts` | อ่านไฟล์จากเบราว์เซอร์ + โหลด `pdfjs-dist@4.10.38` เฉพาะตอนอ่าน PDF |
| `consolidate.ts` | ตรวจ: รหัสซ้ำ (เหมือนกัน = รวมอ้างอิง, ต่างกัน = ประเด็น), ไม่ระบุชั้น/แผน/ภาค (ไม่เดา ไม่นำไปจัดโครงสร้าง), หน่วยกิต≠ชั่วโมง, ยอดไม่ตรง, รหัสไม่ตรงชั้น, เลขไทย, ชื่อซ้อน |
| `compare.ts` | จับคู่แผนและรายวิชาสองปี, ประเภทการเปลี่ยนแปลง 10 แบบ, ยอดรวมต่อภาค/ปี/แผน |
| `structure.ts` / `exporters.ts` | มุมมองโครงสร้างและการส่งออก (ใช้ข้อมูลชุดเดียวกัน) |
| `store.ts` | ที่เก็บระยะ Preview (IndexedDB) |
| `pages/*` | 5 หน้า |

**หลักการนำเข้า:**
- ต้องระบุปีเอง (ไม่เดาจากชื่อไฟล์)
- ชั้น/แผน/ภาคอ่านจากหัวตารางในไฟล์เท่านั้น ถ้าอ่านไม่ได้เป็น `null` และแจ้งเป็นประเด็น
- นำเข้าไฟล์เดิมซ้ำ (sha256) จะแทนที่ข้อมูลเดิมของไฟล์นั้น
- แต่ละไฟล์เป็นแหล่งแยก (PDF ไม่เขียนทับ Excel) และผู้ดูแลเลือกเองว่าไฟล์ใดใช้แสดงผล

## 4. Migration / Backup / Rollback (ยังไม่รัน — ต้องอนุมัติ)
- **Migration `20261207000100_curriculum_v2.sql`:**
  - ตาราง `cv2_curricula`, `cv2_sources`, `cv2_rows`, `cv2_descriptions`, `cv2_import_log` (append-only)
  - RLS:
    - บทบาทหลักสูตรเดิมเห็นทุกสถานะ
    - สมาชิกโรงเรียนทั่วไปเห็นเฉพาะ approved/active
    - ไม่มีสิทธิ์เขียนตรง
  - RPC (ผู้ดูแลหลักสูตรเท่านั้น): `cv2_import_source` (นำเข้า/แทนที่ในธุรกรรมเดียว), `cv2_set_primary`, `cv2_remove_source` (ห้ามเมื่อ approved/active)
  - audit_row_change บนตารางหลัก
  - **ยังไม่มีขั้นตอนอนุมัติ/เปิดใช้ V2** ต้องออกแบบแยก
- **Backup ก่อนรัน:**
  - `pg_dump -Fc` ทั้งฐาน (ตาม `docs/architecture/DATA-TRANSFER.md` ขั้นตอนที่ 1)
  - ตรวจไฟล์ด้วย `pg_restore --list`
- **Rollback:** `supabase/rollback/20261207000100_curriculum_v2.down.sql`
  - ลบเฉพาะวัตถุ cv2_*
  - หยุดถ้ามีหลักสูตร V2 ที่อนุมัติแล้ว
  - สำรอง cv2_* ก่อน
- **หลังรัน Migration:** เปลี่ยน `store.ts` ให้เขียน/อ่านผ่าน RPC/ตาราง cv2_* ส่วนหน้าและตัวอ่านไฟล์ใช้ต่อได้ทั้งหมด

## 6. ข้อจำกัด
- **ที่เก็บระยะ Preview:**
  - เป็นข้อมูลต่อเบราว์เซอร์และต่อเครื่อง จึงไม่ใช่ข้อมูลกลาง
  - ล้างข้อมูลเบราว์เซอร์แล้วจะหาย
  - ครูไม่เห็น
- **ตัวอ่าน PDF:**
  - ทดสอบกับรูปแบบตารางโครงสร้างของเล่มหลักสูตรโรงเรียน (คอลัมน์ภาค 1/2 คู่กัน)
  - PDF สแกนเป็นภาพอ่านไม่ได้ (ไม่มี OCR)
  - คำอธิบายรายวิชาใน PDF อ่านจากรูปแบบหัว “รหัส ชื่อ กลุ่มสาระ…”
- **กลุ่มสาระ:** อนุมานจากอักษรนำหน้ารหัสวิชาตามหลักการตั้งรหัส ยังไม่ผูกกับตาราง learning_areas
- **ห้องเรียน:**
  - แสดงเฉพาะ “ห้องที่ไฟล์ระบุ” และระบุว่ายังไม่ผูกในระบบ
  - ไม่มีการผูกห้องจริง
- **ไฟล์ทดลองฝั่ง 2568:**
  - ใช้ “โครงสร้างหลักสุตรใช้ 68-69-70 ม.25 (1).xlsx” ติดป้าย “ทดลอง”
  - โรงเรียนต้องยืนยันไฟล์หลักสูตร 2568 ฉบับทางการ
